# 開発ワークフロールール

## フェーズ別作業の進め方

### 1. 構築フェーズ
1. 要件を整理し、src/main.ts への追加箇所を特定する
2. @imgly/background-removal のAPIドキュメントを確認する
3. TypeScriptで実装する（src/main.ts に集約）
4. `pnpm dev` でブラウザ動作確認する

### 2. テストフェーズ
1. 各種画像形式（JPEG, PNG, WebP）で背景除去を検証する
2. 大画像でメモリフォールバック（1024→768→512px）を確認する
3. モバイルデバイス（DevToolsまたは実機）でタッチ操作を確認する
4. エラーハンドリング（メモリ不足、ネットワークエラー等）を検証する

### 3. デプロイフェーズ
1. `pnpm build` でビルドが成功することを確認する
2. `pnpm preview` でビルド結果を確認する
3. GitHub Actionsのワークフローを設定する
4. OGP/Twitterカードのプレビューを確認する

### 4. 運用フェーズ
1. ユーザーフィードバックを確認する
2. @imgly/background-removal の更新を監視する
3. パフォーマンス改善を検討する

## チェックリスト

### 構築時チェックリスト
- [ ] 画像アップロード（クリック、ドラッグ&ドロップ）が動作するか
- [ ] 背景除去が正常に実行されるか
- [ ] Canvas上で背景+被写体の合成が正しいか
- [ ] 4種類の背景（銀河/星雲/深宇宙/惑星）が切替できるか
- [ ] 背景切替後に被写体の位置・サイズが維持されるか
- [ ] ドラッグ・スライダー・反転操作が動作するか
- [ ] 保存（PNG）が機能するか
- [ ] シェア/Xポストが機能するか
- [ ] ユーザー画像がサーバーに送信されていないか（Networkタブ確認）

### デプロイ前チェックリスト
- [ ] `pnpm build` がエラーなしで完了するか
- [ ] `pnpm preview` でビルド結果が正しく表示されるか
- [ ] 静的ファイル（bg/*.webp, bg-thumb/*.webp, sample.webp/png）がビルド後も正常か
- [ ] OGP/Twitterカード設定が正しいか

## コーディング規約

### アーキテクチャ
- 全ロジックは `src/main.ts` に集約（フレームワーク不使用）
- 状態はモジュールスコープの `let` 変数で管理
- DOM要素は `document.getElementById()` + 型アサーションで取得
- レンダリングは `requestAnimationFrame` でスロットリング

### TypeScript
- `noUnusedLocals`, `noUnusedParameters` を遵守
- `erasableSyntaxOnly: true`（型のみのインポートはtype修飾子必須）
- DOM操作時はnullチェックまたは `!` アサーション

### Gitコミット
- コミットメッセージは常に日本語で書く
- 変更内容を簡潔に説明する

### コミュニケーション
- 日本語で回答する
- 変更前に確認を取る
