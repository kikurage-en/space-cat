# ドキュメント整合性チェック

## 発動条件

`src/` 配下のファイルを変更するコミット時に、このルールが適用される。

## チェック手順

1. **関連ドキュメントの検索**: 変更した機能に関連する記述が以下のファイルにないか確認する
   - `CLAUDE.md`
   - `.claude/rules/*.md`
   - `.claude/references/*.md`

2. **整合性の確認**: 該当する記述が変更後の実装と一致しているか確認する

3. **同一コミットで修正**: 不一致があれば実装変更と同じコミットでドキュメントも更新する

## チェック対象マッピング

| 変更内容 | 確認すべきドキュメント |
|---------|---------------------|
| カラー値・スタイル変更 | `style-guide.md` |
| 依存パッケージ変更 | `environment-spec.md` |
| API・処理フロー変更 | `CLAUDE.md` の実装パターン節 |
| セキュリティ関連変更 | `security-guidelines.md` |
| ビルド・デプロイ設定変更 | `environment-spec.md`, `development-workflow.md` |

## SSOT原則

- 具体的な値（カラーコード、バージョン番号、初期値等）は **1箇所のみ** に記載する
- 他のドキュメントからは `@参照` で委譲する
- 実装から直接導出可能な値（変数の初期値等）はドキュメントに書かず、ソースコードを参照先とする

## スキルファイルとの関係

`.claude/skills/` 内のSKILL.mdはスキル固有の情報のみ持つ。
実装値の整合性チェック対象は SSOT の委譲先（references, rules, CLAUDE.md）のみ。
